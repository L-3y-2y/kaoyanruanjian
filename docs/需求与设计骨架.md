## 0. 需求复述与待确认清单

### 0.1 你的原话结构化

| 概念 | 定义 |
| --- | --- |
| **大周期** | 用户每天自己选「今天要背的单词数量 N」 |
| **小周期** | 每 5 个单词一组（最后一组可能不足 5 个） |
| **学习阶段（当天）** | 第 1～3 轮，按小周期循环，直到当天 N 个词全部走完 |
| **已背下（初步）** | 走完 R1～R3 的状态。只算「背下来了」，不算真正学完 |
| **真正学完** | 走完 R4～R5 之后的状态。5 轮全走完才算真正意义上学完 |
| **日期批次** | 当天 N 个词完成 R1～R3 后，整体形成一个以「学习日期」命名的批次，永久保存在复习板块 |
| **复习阶段（随时）** | 第 4～5 轮；用户从复习板块任选一个日期批次进入，不设固定时间、不做到期提醒 |
| **每日短文** | 某日期批次 5 轮全走完（真正学完）后才出；把该批次全部单词放进「不算难」的短文供自测 |
| **每周阅读理解** | 每周五晚生成 2 篇，题型类似考研，含本周所学词，给两天作答时间，AI 判分 |
| **技术形态** | **前端 + 后端完整版**（v0.5）：浏览器只负责显示与发音，其余全在服务端 |
| **技术栈**（v0.6 定） | **Vue 3 + Vite / Python + FastAPI / MySQL 8.0 / 浏览器发音 + 后端调免费大模型** |

| 轮次 | 阶段 | 显示什么 | 用户做什么 | 错了 | 对了 |
| --- | --- | --- | --- | --- | --- |
| R1 认词 | 学习·当天 | 只有英文 | 点「认识 / 陌生」 | 点陌生 → 展开读音 + 含义，再点认识才过 | 下一个词 |
| R2 听写 | 学习·当天 | 读音音频（可随时重播） | 拼写英文 | 输入框下方出现正确单词；**重新输入时答案消失** | 自动跳下一个词 |
| R3 默写 | 学习·当天 | 汉语 + 读音音频 | 默写框写英文 | 下方出现正确单词；**重新默写时答案消失** | 回到 R1 开始下一个 5 词小周期 |
| R4 英→中 | 复习·随时 | 英文 | 写汉语释义 | — | 写完显示标准答案 → 用户自评「记住了 / 没记住」→ 下一个词 |
| R5 中→英 | 复习·随时 | 汉语 | 默写英文 | 下方显示正确答案 | 下一个词 |

- **两天作答的逾期规则**：周五晚发布、周日晚截止；逾期还能不能补做、计不计分（默认见第 9 节 B5）。

- **抽词怎么抽**：随机 / 优先没掌握过的 / 保证每个词至少被抽到一次？B2 放宽成「尽力全放」后，怎么向用户交代清楚没覆盖到的词。
- **多篇短文之间**：3 篇各自独立保存还是合成一个「今日短文组」？按钮每篇一个还是共用？
- **同一账号多设备同时登录**：进度以服务端为准，前端不做缓存，天然一致。
- **周次怎么算**：自然周（周一～周日）？周五发布的算哪一周？

## 1. 最核心的一件事：把「进度」当成数据，而不是界面状态

你担心「每次学习时不要重复、不要数据混乱」，**答案就在这一节**。零基础最常见的做法是把今天要背的词放进数组、用下标 `i` 记录第几个，刷新就归零、切轮次被覆盖、答错重来状态丢失。

正确思路：**每个词在每个用户下都有一条独立的、持久化进度记录**，存在服务端。界面只负责把「当前该显示的词」查出来显示，不做任何记忆。**定了前后端之后，这条天然成立**——状态只在数据库一处。

> **v0.6 补一句好消息**：你选了 **Vue**，这条纪律反而更好落地。把「当前词、当前轮次、当前批次」放进 Vue 的响应式数据，界面靠计算属性算出「现在该显示哪个词」——**数据变，界面自动跟着变**，比原生 JS 手动改 DOM 更不容易出现「界面显示的和数据库里的对不上」。但前提是别在组件里再存一份「下标 i」，否则 Vue 也救不了。

### 1.1 一条进度记录至少要能回答这五个问题

| 字段 | 含义 | 举例 |
| --- | --- | --- |
| `user_id` | 谁的进度 | 1 |
| `word_id` | 哪个词 | 882 |
| `round` | 现在在第几轮（1～5） | 2 |
| `cycle_no` | 属于第几个小周期 | 3 |
| `status` | 这一轮是否已完成 | 未完成 / 已完成 |

再加：`daily_plan_id`、`wrong_count`、`updated_at`、`stage`**（已背下 / 真正学完）**。

### 1.2 取词逻辑（思路，不是代码）

```
取下一个词 =
  从进度表里找「属于当前日期批次、且 status = 未完成、round 最小、cycle_no 最小」的一条
  → 显示它 → 用户答对 → 把这条的 status 改成已完成（或 round +1）
  → 再取一次
```

三条纪律：

1. **单一数据源**：状态只存一处（数据库），不要同时存在数组、变量、界面、浏览器缓存里。
2. **答完立刻落盘**：每次答对/答错都写回，不要攒着最后一起存。
3. **取词只靠查询，不靠下标**：不维护「当前第几个」这种游标。刷新、断电、换设备都接着上次继续。

> \[提案\] 把「轮次」做成数据（1～5 存在字段里），而不是写 5 个几乎一样的界面。以后加轮次、改题型只改配置。你同意再采纳。

**这思路同样适用于短文**：「哪些词可点、点过没有」也是状态，也要存服务端（详见 4.2）。

### 1.3 复习板块 = 按学习日期归档的批次

**省事的洞察：你要的「日期批次」，就是那张 **`daily_plan`**（每日计划表），不用另加表。** 它本来就是「某用户某天选了 N 个词」、一天一条。

- 每天完成 R1～R3 → 标成「学习完成」，成为复习板块一行：`2026-11-06 · N 词 · 已背下（初步）`
- 复习板块 = 按 `study_date` 升序列出所有批次，每行一个「进入复习」入口
- 点某一天 → 只取 `daily_plan_id = 那天` 的词走 R4→R5，进度用同一 `daily_plan_id` 关联，不会串到别的日期
- 该批次 R4/R5 全走完 → 升级为「真正学完」，**这一行仍留在列表里**（可回看、可重做）；**此时才触发该批次的每日短文**

三条定死的规则：

1. **新词只从「未掌握池」取**：进过任一批次的词不再参与选词，否则同一个词会落到两个日期组。
2. **批次之间不合并、不覆盖**：11/06 那组永远是 11/06 那组。
3. **复习不设定时器**：静态列表，用户自己点（呼应问题 4）。

> \[提案\] 每个批次加 `review_status`（未复习 / 进行中 / 已完成）与「上次复习时间」。你同意再采纳。

## 2. 数据库：你说的三张表 + 建议补的表

你列的三种都是**静态数据**，软件跑起来靠的是**动态进度**。加文章与测评后约 9 张；**不新增表**——日期批次复用 `daily_plan`。**v0.6 起用 MySQL 8.0（A3 定稿）。**

| # | 表 | 存什么 | 谁会改它 |
| --- | --- | --- | --- |
| 1 | `word` 单词表 | 拼写、音标、中文释义、词性、考研标签、发音音频（可选）、`source` / `verified` | 只有管理员导入/修正 |
| 2 | `user` 用户表 | 用户名、**密码哈希**、注册时间 | 注册时写入 |
| 3 | `admin` 管理员表 | 管理员账号、密码哈希、权限 | 几乎不改 |
| 4 | `progress`** 学习进度表**（你漏的，最关键） | 见 1.1；含 `daily_plan_id`、`stage` 两级状态 | 每次答题都改 |
| 5 | `daily_plan`** 每日计划 / 日期批次表** | `user_id`、`study_date`、N、几个小周期、学习是否完成、`review_status`、`stage` | 每天一条，学习与复习时改状态 |
| 6 | `article`** 文章表** | `user_id`、类型（每日短文 / 每周阅读）、`daily_plan_id` 或周次、标题、正文、`revealed`、**生成模式（全放 / 抽词）**、**收录词 / 未收录提示**、`publish_at`** / **`deadline`、生成方式、生成时间 | 生成时写一次，之后基本只读 |
| 7 | `article_word`** 文章-词关联** | 哪篇文章里、哪个词、正文哪个位置、**当时的汉语释义快照** | 生成时写入 |
| 8 | `question`** 题目表** | 属于哪篇阅读、题型、题干、选项、正确答案/参考答案、`word_id`、`ai_graded` 标志 | 生成时写入 |
| 9 | `answer_log`** 答题记录** | 谁、哪题、答了什么、对不对、**AI 判分结果/理由**、时间 | 每次答题写 |

**设计要点：**

- `word` 与 `progress` 一对多：一个词对多个用户各有一条进度，多人互不干扰。
- `daily_plan`** 是「日期批次」的载体**：文章、进度、每周阅读都挂在它上面，共用同一个日期维度。
- **密码字段永远叫 **`password_hash`，存哈希不是明文（第 7 节）。
- `admin` 表第一阶段可以先不要——先用导入脚本把词库灌进去，最后再做管理界面。
- 词库表留 `source` / `verified`，标记「来自哪个开源库、是否人工核对过」，这是「保证考研单词正确性」的落点。
- 文章、题目按 `user_id` 隔离；`article_word` 存**释义快照**，否则管理员改了词库，三个月前那篇短文点开显示的意思就变了。
- `word.word`** 建唯一索引**：从数据库层面杜绝重复词，这是「不重复」最硬的一道保障（呼应 B1）。

### 2.1 MySQL 版建库口径（v0.6 新增，都是要点不是代码）

换成 MySQL 后，下面五条是零基础最容易踩的坑，**动手建表前先记住**：

| # | 要点 | 不这么做会怎样 |
| --- | --- | --- |
| 1 | **建库指定 **`utf8mb4`** 字符集 + 对应排序规则** | 中文释义、汉语题目、短文正文存进去变问号。这个软件一半内容是中文，字符集是第一个必过的关 |
| 2 | `study_date`** 用 **`DATE`** 存 **`YYYY-MM-DD`**，不要带时区的类型** | 整个复习板块按日期归档，时区一乱会出现「11/06 的词跑到 11/07」，日期批次就串了 |
| 3 | **主键用自增整数，正文用 **`TEXT`** 一类长文本类型** | 从 SQLite 教程抄过来的 `AUTOINCREMENT` 写法在 MySQL 里不通用；短文正文塞进短字符串会被截断 |
| 4 | **「改进度 + 写答题记录」放在同一个事务里** | 直接兑现 1.2 的「答完立刻落盘」和第 6 节的「防重复提交」；答题记录写成功而进度没写上，就会出现同一个词重复出现 |
| 5 | **连接串（地址 / 库名 / 账号 / 密码）只放后端 **`.env` | 和 API Key 一样，不进仓库、不下发浏览器 |

> **ECDICT 自带的 SQLite 只是「数据源格式」**：用一次性导入脚本把它的 CSV / SQLite 读出来，写进你的 MySQL，不是让你把数据库换成 SQLite。第 3.1 节的用法不变。
> MySQL 没有「复制一个 `.db` 文件」这种备份方式了，改用导出 SQL 文件备份；**别用删库重建来修数据**。

## 3. 词库、发音与内容生成

### 3.1 两个可用的开源词库

| 源 | 特点 | 怎么用 |

### 4.1 每日短文：生成、多篇、抽词、告知

生成方式：免费大模型（3.3 节）。流程建议：

```
输入 = 该批次今日词表 + "写一篇不难的英文短文，尽量自然嵌入这些词"
生成 → 覆盖率校验（逐个词在正文里找，列漏词）
```

**「告知用户」是硬性要求**。建议界面固定一行提示：

### 5.0.1 目录结构与建库实操（Navicat）

**① 子文件夹就是在项目根文件夹里建**，现在只建空的就行，不用先往里放东西：

```
kaoyan-vocab/                 ← 项目根文件夹，路径纯英文 / 无空格 / 无中文
├─ frontend/                  ← Vue 3 + Vite 工程（阶段 1 起）
├─ backend/                   ← FastAPI 代码、.env（阶段 2 起）
├─ scripts/                   ← 词库导入等一次性脚本
├─ data/                      ← ECDICT 原始 CSV / SQLite 源文件
├─ docs/                      ← 本文档、接口契约、设计决策记录
├─ .gitignore                 ← 放根目录，第一天就建
└─ .env.example               ← 放根目录，只写键名不写真值
```

**② 先分清 Navicat 里三层东西**，这决定「重新注册一个」到底该做什么：

| 名词 | 是什么 | 要不要新建 |
| --- | --- | --- |
| **连接** | Navicat 连到某个 MySQL 服务的**入口**；一个连接能看到该服务下所有库 | ❌ 通常不用 |
| **数据库（schema）** | 服务里逻辑隔离的一块，**一个软件一个库** | ✅ 新建一个，如 `kaoyan_vocab` |
| **账号** | 权限身份，可限制成「只能读写这一个库」 | ✅ 推荐建专用账号，也可等阶段 4 再补 |

所以「想重新注册一个只为这个软件服务的」= **在现有连接里新建一个库 + 建一个只授权这个库的账号**。不是重装 MySQL、也不是新建第二个连接：装第二个实例会抢 3306 端口、两个服务打架；新建连接只是同一服务的第二个入口，看到的库还是一样的，达不到隔离目的。**新库与旧库逻辑隔离，不会影响之前那个项目的数据。**

**③ Navicat 图形界面步骤：**

1. 双击现有连接能展开 → 说明 MySQL 服务在跑，**不用另装**
2. 右键连接 → **新建数据库**：库名 `kaoyan_vocab`（英文小写 + 下划线，别用中文 / 空格 / 连字符）→ 字符集 `utf8mb4` → 排序规则 `utf8mb4_0900_ai_ci`（MySQL 8.0 默认）或 `utf8mb4_unicode_ci`，二选一别混。（对应语句：`CREATE DATABASE`）
3. **验证中文**：选中刚建的库 → 新建查询 → 建一张临时测试表（`CREATE TABLE`）→ 插一条中文（`INSERT`）→ 读出来（`SELECT`）确认不是问号 → 删掉临时表（`DROP TABLE`）。**光查字面量不算数，要验证表的字符集**
4. （推荐）**用户 → 新建用户**：如 `kaoyan_app`、主机 `localhost`、设密码 → 权限里**只勾 **`kaoyan_vocab`** 这一个库**，给读写权限 → 保存。（对应语句：`CREATE USER` + `GRANT`）以后后端用这个账号连，碰不到别的项目的数据
5. 把主机 / 端口 / 库名 / 账号 / 密码写进后端 `.env`——**只留在你本机，别贴给我、别进 Git**
6. 确认 `.gitignore` 里包含 `.env`

**④ 四个容易出事的地方：**

- **MySQL 的 **`utf8`** 是假的**：它其实是 `utf8mb3`，生僻字和 emoji 存不下，必须选 `utf8mb4`
- **每次执行前看一眼顶部选中的库名**，确认是 `kaoyan_vocab`。别在旧库里建表，更别对旧库做删除操作——你要的隔离，第一步是把「操作对象」认对
- **建库当天就验证中文**：释义、短文、题目一半内容都是中文，别等阶段 3 导入 5500 词后才发现全是问号
- 若现有连接指向的是**云上的数据库实例**而非本机 MySQL，做法相同：在平台上新建一个库/实例、Navicat 加一个连接指过去，字符集同样 `utf8mb4`；另外记得配访问白名单

> 上面每一步都给了对应的语句名，图形点完即可。想练手写 SQL 就自己把这些语句敲一遍，我不代写——这是环境配置，不算软件代码。

### 5.0.2 库建好之后：先确认字符集，再认识 1064

**① 比验证中文更优先的一步：确认「库级」字符集是 **`utf8mb4`**。**

表默认继承所属库的字符集。库建错了，后面建的所有表都是错的，等阶段 3 导入 5500 词才发现全是问号就晚了。做法：右键 `kaoyanruanjian` → **编辑数据库 / 属性** → 看「字符集」是不是 `utf8mb4`；不是就改过来保存。

- 排序规则选 `utf8mb4_0900_ai_ci`（MySQL 8.0）或 `utf8mb4_unicode_ci`，二选一别混
- 若列表里**根本没有 **`0900`** 那个**，说明服务不是 MySQL 8.0（可能是 5.7 / MariaDB），选 `utf8mb4_unicode_ci` 即可，不影响功能
- 共享 / 教学实例上常有一堆示例库（`sakila`、`world`、`education`…），**别照着它们的字符集抄**

**② 常见报错 1064：查询框里写的是「命令」，不是「数据」。**

在查询编辑器里直接敲「哈哈」再点运行，会得到：

```
1064 - You have an error in your SQL syntax; ... near '哈哈' at line 1
```

| 你写的 | MySQL 怎么理解 |
| --- | --- |
| `哈哈` | 一条名为「哈哈」的**命令** → 没有这条命令 → 报语法错误 |
| 一条完整语句（动作 + 操作对象 + 内容，中文放引号里） | 才是一条能执行的命令 |

**这不是乱码、不是库建错、也不是中文存不进去。** 反过来，报错信息里「哈哈」能正常显示，恰恰说明客户端和服务端之间中文传输是通的——但它**不能证明表的字符集**，因为既没建表也没存数据。

**③ 正确验证中文的两条路：**

- **图形法（推荐，零基础最稳）**：右键库下的「表」→ 新建表 → 加一列字符类型、字符集选 `utf8mb4` → 保存 → 双击打开 → 在网格里手打「考研单词」→ 能正常显示并保存即通过 → 删掉这张测试表
- **手写语句法（练手）**：按「建表 → 插入 → 查询 → 删表」四步自己把语句敲出来（对应 `CREATE TABLE` / `INSERT` / `SELECT` / `DROP TABLE`）。一条语句 = 动作关键字 + 操作对象 + 具体内容，**中文数据要放在引号内**；表名列名自己定，我不代写

> **验证不是开工硬门槛。** 库建好、字符集确认、选中了正确的库，就可以回到阶段 0 的伪代码。等阶段 2 真正建 `progress` 表时顺手插一条中文验证，一举两得，不必卡在环境这一步。

**④ 从实际截图看到的三点：**

- 一个连接下常有多个库，**每次执行前看一眼顶部下拉框**，确认是 `kaoyanruanjian` 再运行。别在别人的库里建表，更别做删除操作
- 若这是**共享 / 教学用的 MySQL 实例**，第 ③ 步的「建专用账号」可能没权限，做不了就跳过：用现有账号连接，隔离靠「库名 + 每次选中正确库」保证，不影响开发
- 文件夹名与库名**同名完全没问题**：一个在磁盘、一个在 MySQL 里，是互不相关的两样东西

### 5.0.3 想「换个干净的地方」：连接不是文件夹

**关键事实：Navicat 左侧顶层是「连接」＝连到某台 MySQL 服务器的窗口，不是装数据库的文件夹。**

- 库属于**服务器实例**，不属于连接。同一台服务器上的所有库，从任何一个指向它的连接里都看得到。
- 所以新建一个连接、连接名填 `kaoyanruanjian`，只要主机 / 端口 / 账号还是同一台服务器，展开后**照样是 education / sakila / world 那一大堆**；已有的库也不会「搬」过去。连接名只是个显示标签。
- 截图里 `L` 与 `myco305` 两个连接列出几乎相同的库列表，正说明它们只是同一台服务器的两个窗口。
- 也正因为如此，**不能在「连接」这一层旁边再建一个平行的专属文件夹**：数据库只能建在某台服务器（连接）里面。

按「嫌乱、想只看到自己的东西」这个真实诉求，从省事到彻底三条路：

| 做法 | 效果 | 备注 |
| --- | --- | --- |
| ① 右键 `L` → **重命名连接**为 `kaoyanruanjian` | 顶层名字统一，库和数据一个字节都不动 | 零风险，最省事 |
| ② 建**专用账号**只授权 `kaoyanruanjian` 一个库，再用该账号新建连接 | 展开后**真的只看到自己的库**，最贴合「干净」 | 共享 / 教学实例可能没有建账号权限，做不了就跳过（见 5.0.1） |
| ③ 装第二个独立 MySQL 实例 | 物理隔离 | ❌ 抢 3306 端口、两个服务打架，**别做** |

**别为了「换个地方」删库重建**：库现在是空的（还没建表），删了重来只是把同一件事再做一遍，还容易顺手点错别人的库。真已经删了也不要紧，重新建一个空的即可，没有任何损失。

**另一个可能的误解**：表就是**直接建在 **`kaoyanruanjian`** 库下面**（右键库下的「表」→ 新建表），不需要再新建一层容器来装它——**库本身就是那个容器**。你说的「在这个里面建立别的东西」，现在就能做。

> 若新建库后左侧树里看不到它：右键连接 → **刷新**。查询栏的数据库下拉还显示着旧名字，是上次选中状态的缓存，不代表库还在。

### 5.0.4 采纳方案 ②：专用账号 + 新连接（让连接里只显示自己的库）

**原理**：一个连接能看到哪些库，取决于**该连接所用账号被授权了哪些库**。用一个只被授予 `kaoyanruanjian` 的账号建连接，展开后就只有这一个库——这才真正实现「连接名叫 `kaoyanruanjian`、里面只装这个软件的东西」。

**前置条件**：需要建账号 / 授权的权限。教学 / 共享实例常不给（截图里 `L`、`myco305` 带一堆示例库，很像机房服务器）。**先花 30 秒验证**：选中连接 → 工具栏「**用户**」→ 试「新建用户」；若提示无权限或保存失败，直接跳到文末「权限不足」的降级，别卡在这里。

**Navicat 图形步骤：**

1. 选中 `L` → 工具栏「**用户**」→ 新建用户
2. 用户名 `kaoyan_app`（英文、别用 `root`、别用中文）；主机 `localhost`（程序与 MySQL 在同一台机器时）
3. 设密码，自己存好，**别贴给我、别进 Git**
4. **保存前**先把各选项卡按下面这段检查一遍（见下方要点），再点「保存」

> **「常规」页与其余选项卡的填写要点（v0.6.6 补，都在点保存之前做）**
>
> - **「过期密码策略」选 **`NEVER`**（永不过期）**。[Navicat 官方文档](https://www.navicat.com.cn/company/aboutus/blog/326-%E5%9C%A8-navicat-premium%E4%B8%AD%E7%AE%A1%E7%90%86-mysql-%E7%94%A8%E6%88%B7%EF%BC%8D%E7%AC%AC-2-%E9%83%A8%E5%88%86%EF%BC%9A%E5%88%9B%E5%BB%BA%E6%96%B0%E7%94%A8%E6%88%B7)说明 `NEVER`「对脚本和其他自动化过程很有用」——后端程序正是这类账号；`DEFAULT` 在 MySQL 5.7.11+ 也等于不过期（默认 0 天），但 `NEVER` 更明确，不受服务器全局策略改动影响。**千万别选 **`IMMEDIATE`：那会让后端第一次连接就报「密码已过期」，`INTERVAL` 也没必要（隔一阵子程序突然连不上，最难查）。
> - **「插件」保持 **`mysql_native_password` 就好：对 Python 驱动的兼容性比 MySQL 8.0 默认的 `caching_sha2_password` 省事，阶段 2 少踩一个坑。
> - 切到「**权限**」页 → 对象范围**只选 **`kaoyanruanjian`** 这一个库** → 勾开发期所需权限（增删改查 + 建表 / 改表）。**千万别点「全部数据库」**，否则又变成什么库都能看见。
>
> **「权限」页那张表格逐列怎么填（v0.6.7 补，截图里的实际界面）**
>
> - 表格**一行 = 对一个对象的授权**。先点工具栏「**添加权限**」新增一行（有些版本点了会弹窗让你先勾选数据库）。
> - **「数据库」列绝不能留空**：点那个空白单元格会出现下拉，只选 `kaoyanruanjian`。留空或选了「全部 / `%`」，要么保存报错、要么变成对所有库授权，前面「只显示自己那个库」就白做了。截图里正是**数据库列空白、**`Select`** 却已勾上**的状态——必须先把库选上。
> - **「名」列留空**：留空表示对该库下所有对象生效；填了具体名字就只对那一张表生效（现在别填）。
> - **该勾的**：`Select`、`Insert`、`Update`、`Delete`（增删改查）＋ `Create`、`Drop`、`Alter`、`Index`（建表 / 改表 / 建索引，阶段 2 建表要用）。

> - **「服务器权限」页一个都别勾**、**「高级」页留空默认**。勾了服务器级权限，新账号又能看到或修改所有库，「只显示自己那个库」就白做了。
> - 点一下「**SQL 预览**」页：Navicat 会把刚才这些图形操作对应的语句显示出来。这是看语句长什么样、练 SQL 的好机会，也不算代写。
> - 以上都确认完，再点左上角「**保存**」。

1. 顶部「**连接**」→ 新建连接 → 连接名填 `kaoyanruanjian`（这一层只是显示标签，可以随便起）→ 主机 / 端口与 `L` 相同 → 账号密码填 `kaoyan_app` → **测试连接** → 确定
2. 展开新连接：应只看到 `kaoyanruanjian`（外加 `information_schema` 之类系统库，属正常）
3. **后端 **`.env`** 换成新账号**：主机 / 端口 / 库名不变，账号密码换成 `kaoyan_app` 的

**四个坑：**

- **新账号默认没权限**，必须显式给这一个库授权；否则新连接连上看不到库，你会以为「库丢了」。库一直在服务器上，只是这个账号看不见。
- **别删原来的 **`L`** 连接**：留作后路，新账号权限不够时随时切回去。
- **一个库、两个账号指向它，数据是同一份**，不会分叉；`L` 用旧账号、新连接用新账号都能操作它。
- **权限不足就降级**：右键 `L` → 重命名连接为 `kaoyanruanjian`（方案 ①），零风险、效果接近，**不影响任何开发**。别为追求「绝对干净」去装第二个 MySQL 实例。

> 连接名与库名都叫 `kaoyanruanjian` 不冲突：一个只是 Navicat 里的显示标签，一个是服务器上真实的数据容器。
> 如果程序以后不跑在 MySQL 同一台机器上，`localhost` 要换成对应主机 / 授权范围，届时再调，现在按同机走。

## 7. 安全底线

1. **密码绝不能明文存**。注册时算哈希（Python 用 `bcrypt` / `passlib`，或框架自带的 `generate_password_hash`），登录时只比对哈希。列名 `password_hash`。管理员同样处理。
2. **别把词库、密钥、数据库凭据提交到公开仓库**。`.gitignore` 第一天就建好，`.env`（含 API Key 和 MySQL 连接串）、构建产物、导出的词库数据都要在里面。**v0.6：MySQL 没有 **`.db`** 单文件了，别照抄旧教程的 **`*.db`** 规则。**
3. **API Key 与数据库连接串只放后端 **`.env`（环境变量），永远不下发到浏览器。v0.5 定了前后端之后这条自然成立。([密钥安全提醒](http://m.hangge.com/news/cache/detail_5047.html))
4. **给免费源设兜底和用量上限**：单家挂了能切，别让生成逻辑失控刷额度。
5. **免费政策会变**：Agnes 与各国内平台的免费额度、模型名都可能调整，动手前到官网核实，别把具体模型名写死在业务逻辑里。
6. **接口要校验登录态**：每个涉及用户数据的接口都先确认「这是谁」，别只靠前端挡。多用户隔离是后端的责任，不是前端的。
7. **【v0.6】开发期的请求转发只在本机生效**：Vite 那条转发配置是开发便利，别把它当成上线后的安全边界；交付时页面与接口由 FastAPI 同源托管。
