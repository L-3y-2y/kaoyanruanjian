> 本文描述项目**当前实际状态**（截至 2026-11-20），涵盖技术栈、目录结构、分层架构、数据库、接口、五轮状态机、内容生成链、AI 答疑、模型切换、安全边界、部署与自检。

## 1. 一句话定位

一个**前后端分离、数据落 MySQL、可接大模型的考研英语单词学习系统**。核心不是"又一个背单词 App"，而是三条自研主线：**五轮记忆状态机**（把"学过/记住"拆成两个可验证的状态）、**有质量护栏的 AI 内容生成**（覆盖率校验 + 漏词重写 + 本地降级）、**限定域的 AI 英语答疑**（带真实语境快照、旁路不计分）。

## 4. 分层架构

```
浏览器 (Vue 3)
   │  相对路径 /api/*，只带 HttpOnly Cookie，从不传 user_id
   ▼
FastAPI (单端口同源托管前端 dist)
   ├─ auth.py       身份解析：每个数据接口从 Session Cookie 定 user_id
   ├─ main.py       路由层：参数校验、事务边界、错误码
   ├─ ───────────── 业务层 ─────────────
   │   ├─ 五轮状态机（取词/判定/跃迁，全在 main.py + progress 表）
   │   ├─ content.py  内容生成与判分
   │   └─ chat.py     AI 答疑（旁路）
   ├─ llm.py         统一生成层：主备切换、JSON 提取、模型切换、连通性测试
   └─ db.py          事务封装 + 幂等迁移
   ▼
MySQL 8.0 · kaoyanruanjian（12 张表）
   ▼
外部：智谱 / Agnes（OpenAI 兼容 HTTP）；无 Key 时 content.py 本地模板兜底
```

**三条铁律**（贯穿全项目，见 `main.py` 文件头）：

1. 进度只存在 MySQL，前端不保存游标/下标；
2. 取词靠查询 `status=pending` 排序，不靠游标递增；
3. 每次答题在**同一事务**里完成"改 progress + 写 answer_log"。

旁路模块（短文、周阅读、AI 答疑）**永不写 progress**，因此不影响五轮状态与两级掌握。

## 5. 数据库设计（12 张表）

| 表              | 作用                | 关键约束                                             |
| -------------- | ----------------- | ------------------------------------------------ |
| `user`         | 用户账号              | `uk_username` 唯一；id=1 为 `local` 占位账号             |
| `admin`        | 管理员账号             | 独立表，与 user 的会话靠 `is_admin` 区分，不串号                |
| `user_session` | 服务端 Session       | token 主键，`is_admin` 标志,过期时间                      |
| `word`         | 词库（ECDICT 4803 词） | `uk_word` 唯一，`exchange` 存词形变化                    |
| `daily_plan`   | 每日计划              | `uk_user_date`；`memorized_at`/`mastered_at` 双时间戳 |
| `progress`     | 每词每轮的进度           | `uk_user_word_round`；`idx_fetch` 支撑取词            |
| `answer_log`   | 答题流水              | 记录每题作答、判分理由、是否逾期                                 |
| `article`      | 短文/周阅读正文          | `scene` 场景；按批次/周次幂等唯一键                           |
| `article_word` | 词在文中的标注快照         | **生成时存下释义**，词库改了老文章不变                            |
| `question`     | 周阅读题目             | 4 道客观 + 1 道主观，含参考答案与 AI 判分标志                     |
| `chat_session` | AI 答疑会话           | 存冻结的语境快照与轮数；**旁路表**                              |
| `chat_message` | AI 答疑消息           | 按 session 聚合，按 user_id 隔离；**旁路表**                |

迁移策略：`schema.sql` 全是 `CREATE TABLE IF NOT EXISTS`；`db.py:ensure_columns()` 用 `information_schema` 检查后逐个 `ADD COLUMN`，只增不删，重复启动绝对安全，老数据零丢失。

## 6. 五轮记忆状态机（核心资产）

一个词从进入计划到"真正学完"，要走过两级状态、五轮题型：

```
建计划(N 词，按 5 词/组分周期)
   │
   ▼
R1 认词 ── R2 听写 ── R3 默写        ← "今日学习"（LearnView）
   │  走完全部词的 R1~R3
   ▼
daily_plan.stage = memorized（初步背下），写入 memorized_at
   │
   ▼
R4 英→中 ── R5 中→英                 ← "复习板块"（ReviewView）
   │  走完全部词的 R4~R5
   ▼
stage = mastered（真正学完），写入 mastered_at；此后该批次出现每日短文
```

- **两级状态分开存**：`memorized_at`（初步）与 `mastered_at`（真正）是两个独立时间戳，不是布尔值，能回答"什么时候初步记住、什么时候真正掌握"。
- **答错处理**：`wrong_count` 累计；拼错当场显示正确答案，不跳过；间隔复习开启时答错会把下次复习缩回 1 天。
- **幂等防重复**：更新带 `WHERE status='pending'`，影响 0 行即视为重复提交，直接返回最新 state，不报错、不跳词。
- **可选增强**：`SMART_REVIEW=1` 才写 `review_stage/last_review_at/next_due_at`，按 1/2/4/7/15/30 天排期；默认 `0`，严格保持原需求"按日期批次、无到期提醒"。

## 7. AI 内容生成链（带质量护栏）

三处用 AI：每日短文、周阅读题目、主观题判分。统一走 `llm.py` 的 `generate_text()/generate_json()`。

**短文生成**（`content.py`）：

1. 模型被要求返回 JSON（标题 + 正文），按选定场景写；
2. 用**与"点词释义"完全相同的词形还原表**校验目标词覆盖率（复数/过去式/句首大写都能匹配）；
3. 漏词 → 带缺失清单重写一次；仍不达标 → 退回本地模板（已重写为自然句式，无 "The word X appears here" 硬凑）；
4. 生成时把每个词的释义快照写入 `article_word`，保证"点开是生成当时的意思"。

**周阅读**：模型按文章一次生成 4 道四选一 + 1 道简答及评分要点，校验选项/答案格式；失败回退模板。主观题判分结果按"参考答案+作答"缓存（LRU），重复提交不烧额度。

**多源与降级**：主源智谱 + 兜底 Agnes，都是 OpenAI 兼容协议，地址/Key/模型名全从 `.env` 读，业务逻辑不写死模型名。无 Key 时全流程走本地确定性生成器，功能完全可用。

## 8. 互动与英语 AI 助手

**已有互动**：短文揭示后自动生成最多 5 道语境完形填空（干扰项取自同篇其他词，答错显示释义）；纯前端练习，不写库。

**英语 AI 助手（chat.py + ChatPanel.vue）**——这是设计上最克制的模块：

- **旁路性**：会话与消息只写 `chat_session`/`chat_message`，**不碰 progress/answer_log/两级状态**。实测对话前后 progress 75→75、answer_log 50→50。
- **真实语境（可选增强，不是边界）**：从短文或题目打开时，把文章正文、题干选项、以及 `article_word` 里的**真实释义快照**冻结进会话 `context`，回答关于这篇内容的问题时作为 ground truth 防编造；**从导航直接打开则没有语境，照样能查词、互译、讲语法**。
- **能力范围**：系统提示允许任意英语学习话题——中英互译、单词查询（释义/音标/词性/搭配/例句）、语法与句法分析、写作润色、阅读题讲解；非英语问题会礼貌拒答并引导回英语。回答语言跟随提问：汉译英先给英文、英译汉先给中文，其余按用户语言，必要时补双语例句。
- **成本与体验护栏**：最多 8 轮、每次回复 512 token 上限、只回传最近 12 条历史；未配 Key 时禁止开启。
- **三个入口**：通用「英语 AI」、短文「问 AI · 这篇文章」、周阅读逐题「问 AI」；点词卡片可「追问这个词」。
- **越权防护**：带来源的会话只在本人的 article/question 上建立，来源不存在或不属于本人直接 404。

## 9. 账号、权限与安全边界

- **身份**：除 health 与 auth 外，所有接口从 HttpOnly Session Cookie 解析 user_id，**绝不采信前端传来的用户 id**；跨账号访问一律 404。
- **口令**：PBKDF2 200k 轮 + 随机盐；密码框按模式区分 `new-password`/`current-password`。
- **限速**：登录/注册/管理员登录 5 次/60 秒锁定，成功清零。
- **注册继承竞态**：首次注册继承旧进度用 `SELECT ... FOR UPDATE` 行锁 + 当前读计数，避免并发重复搬数据。
- **管理员边界**：`ALLOW_LOCAL_ADMIN` 开关 + 拒绝 `X-Forwarded-*` 转发头，防止反向代理下外部访客提权；`GET /api/auth/users` 需管理员权限。
- **健康接口**：不回显数据库账号，页面不展示凭据。
- **模型边界**：Key 与 base_url 永不下发浏览器；模型切换只能在服务端白名单 `LLM_MODEL_PRESETS` 内选，非法名直接拒绝。
- **SQL**：全部参数化查询，注入面基本为零。

**已知未修（可在答辩中主动说明）**：`GET /api/state` 带副作用（无 pending 时会做状态跃迁）；长事务跨 LLM 网络调用可能持锁 30~60 秒；`answer_log` 缺唯一键兜底并发重复。这些在单机自用下不触发，改动面大故暂缓。

## 10. 模型切换与连通性测试

- 顶部状态条显示「已接 · 具体模型名」或「本地生成」，点击弹出 `ModelPanel`。
- **白名单**：只列服务端 `LLM_MODEL_PRESETS` 里的模型（默认 `glm-4-flash / glm-4.5-flash / glm-4.7-flash`），不暴露 Key 和地址。
- **切换三件事**：改 `os.environ`（下次生成立即生效、无需重启）→ 清判分缓存 → 写回 `.env` 的 `LLM_MODEL=` 行（重启保持）。写回逐行替换且加线程锁，Key 行与其他配置原样保留。
- **连通性测试**：`POST /api/llm/test` 真发一句极简请求，把 HTTP 429 等真实错误显示出来——修掉"状态条显示已接、实际限流却静默回退"的误导。实测中发现 `glm-4.5-flash` 限流即由此暴露。

## 13. 自检与验证

`scripts/verify_full.py` 是**真端到端**自检（真实 HTTP + 真实 MySQL，非 mock），覆盖 13 项 + 2 个附加项：

- `[0]` 老数据快照前后一致（运行时动态发现主键，不硬编码）
- `[1]～[6]` health、注册登录、Session、N=18 建 4 组、R1～R5 各 18 题、两级状态跃迁
- `[7]～[8]` 短文幂等、首次纯文本、每次揭示重置、词形标注
- `[9]～[11]` 周阅读 2 篇 10 题、客观判分 + 主观 AI 判分理由、防重复、成绩汇总
- `[12]` 多用户隔离、空周兜底
- `[3a]` 真实管理员权限（本机放行 / 普通账号 403 / 用户枚举 403）
- `[12a]` 模型切换 → 探测 → 恢复闭环（跑完必恢复原模型）

所有测试数据落在临时账号下，`finally` 中自动删除，绝不碰你的真实进度。可用 `VERIFY_BASE` 指定端口以便在已运行的服务旁并行自检。

**本版本验证结果**：后端语法、前端构建通过；13 项全过（真实大模型生成下）；对话全流程实测通过（含旁路隔离、语境约束、越权 404）；老数据 2 计划 / 75 行 progress / plan 9 mastered 前后完全一致。

## 14. 对外展示要点（简历/比赛/复试）

最具技术含量的四点：**五轮状态机 + 两级时间戳**、**释义快照闭环 + 词形还原**、**覆盖率校验 + 漏词重写**、**限定域 AI 答疑的旁路设计与幻觉约束**。答辩叙事："用自己的技术解决自己的备考痛点"。AI 辅助编码如实归因——需求设计与架构决策自主主导，编码用 AI 辅助、逐行审核测试；重点是能讲透每个设计取舍（详见 `docs/design-decisions.md` 与 `docs/项目评审与包装指南.md`）。
