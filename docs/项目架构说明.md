> 本文描述项目**当前实际状态**（截至 2026-11-20），涵盖技术栈、目录结构、分层架构、数据库、接口、五轮状态机、内容生成链、AI 答疑、模型切换、安全边界、部署与自检。

## 1. 一句话定位

一个**前后端分离、数据落 MySQL、可接大模型的考研英语单词学习系统**。核心不是"又一个背单词 App"，而是三条自研主线：**学习 + 艾宾浩斯复习状态机**（把"学过/记住"拆成两个可验证的状态）、**有质量护栏的 AI 内容生成**（覆盖率校验 + 漏词重写 + 本地降级）、**限定域的 AI 英语答疑**（带真实语境快照、旁路不计分）。

## 4. 分层架构

```
浏览器 (Vue 3)
   │  相对路径 /api/*，只带 HttpOnly Cookie，从不传 user_id
   ▼
FastAPI (单端口同源托管前端 dist)
   ├─ auth.py       身份解析：每个数据接口从 Session Cookie 定 user_id
   ├─ main.py       路由层：参数校验、事务边界、错误码
   ├─ ───────────── 业务层 ─────────────
   │   ├─ 五轮状态机（取词/判定/跃迁，全在 main.py + progress 表）
   │   ├─ content.py  内容生成与判分
   │   └─ chat.py     AI 答疑（旁路）
   ├─ llm.py         统一生成层：主备切换、JSON 提取、模型切换、连通性测试
   └─ db.py          事务封装 + 幂等迁移
   ▼
MySQL 8.0 · kaoyanruanjian（12 张表）
   ▼
外部：智谱 / Agnes（OpenAI 兼容 HTTP）；无 Key 时 content.py 本地模板兜底
```

**三条铁律**（贯穿全项目，见 `main.py` 文件头）：

1. 进度只存在 MySQL，前端不保存游标/下标；
2. 取词靠查询 `status=pending` 排序，不靠游标递增；
3. 每次答题在**同一事务**里完成"改 progress + 写 answer_log"。

旁路模块（短文、周阅读、AI 答疑）**永不写 progress**，因此不影响五轮状态与两级掌握。

## 5. 数据库设计（19 张表）

| 表              | 作用                | 关键约束                                             |
| -------------- | ----------------- | ------------------------------------------------ |
| `user`         | 用户账号              | `uk_username` 唯一；id=1 为 `local` 占位账号             |
| `admin`        | 管理员账号             | 独立表，与 user 的会话靠 `is_admin` 区分，不串号                |
| `user_session` | 服务端 Session       | token 主键，`is_admin` 标志,过期时间                      |
| `book`         | 四本书（考研/四/六/高考）  | `uk_book_code`；`tag_filter` 对应 ECDICT 考试标签             |
| `word`         | 词库（7395 词，多标签）  | `uk_word` 唯一，`exchange` 存词形变化；一个词可属于多本书          |
| `daily_plan`   | 每日计划              | `uk_user_book_date`；`book_id` + 双时间戳                 |
| `progress`     | 每词每轮的进度           | `uk_user_book_word_round`；`idx_fetch` 支撑按书取词          |
| `answer_log`   | 答题流水              | `book_id`；记录每题作答、判分理由、是否逾期                         |
| `article`      | 短文/周阅读正文          | `book_id` + `scene`；按书/批次/周次幂等唯一键                  |
| `article_word` | 词在文中的标注快照         | **生成时存下释义**，词库改了老文章不变                            |
| `question`     | 周阅读题目             | 4 道客观 + 1 道主观，含参考答案与 AI 判分标志                     |
| `word_example`   | 语境填空历史例句      | `(word_id, book_id, seq)` 唯一，用于"同词不再重复"去重            |
| `article_cloze`  | 短文语境填空题        | `(article_id, word_id, source)` 唯一，答案服务端留存，答错标记薄弱 |
| `chat_session` | AI 答疑会话           | `book_id` + 冻结语境快照与轮数；**旁路表**                       |
| `chat_message` | AI 答疑消息           | 按 session 聚合，按 user_id 隔离；**旁路表**                |
| `study_time`   | 今日学习时长           | `(user_id, study_date)` 主键，前端心跳累计                     |

迁移策略：`schema.sql` 全是 `CREATE TABLE IF NOT EXISTS`；`db.py:ensure_columns()` 用 `information_schema` 检查后逐个 `ADD COLUMN`，`ensure_indexes()` 用 `_rebuild_unique()` 比对索引列后重建（只在列不匹配时 ALTER），只增不删，重复启动绝对安全，老数据零丢失。多书籍迁移可单独跑 `scripts/migrate_books.py` 看报告。

**多书籍隔离**：`user.current_book_id` 记住当前书，认证层把 `book_id` 带进请求上下文；所有取词、进度、统计、短文、阅读、AI 接口都按 `(user_id, book_id)` 过滤。书籍是词库上的标签视图，不是词条复制。老数据全部归 `book_id=1`。

## 6. 学习 + 艾宾浩斯复习状态机（核心资产）

一个词要经历「学习 5 轮 → 艾宾浩斯复习」两条主线：

```
建计划(N 词，滑轴 1~100，按 5 词/组分周期)
   │
   ▼
R1 认词 ─ R2 听音默写 ─ R3 看义默写 ─ R4 看词写义 ─ R5 看义默写  ← "学习"（LearnView）
   │  走完全部词的 R1~R5
   ▼
stage = memorized（已学完），写入 memorized_at，进复习池；每日短文解锁
   │
   ├─ 短文：读全文看今日词在文中的意思
   └─ 语境填空：按考试难度现写新句（不抄原文、不重复），填英文单词；答错标记薄弱
   │
   ▼
次日复习：cloze_wrong 的词优先安排，三轮通过清零标记
   │
   ▼
按 1/2/4/7/15/30 天间隔到期召回（词级，非批次级）
   │  每次复习走三轮：① 认不认识 → ② 听音默写 → ③ 汉译英默写   ← "复习"（ReviewView）
   ▼
三轮全过 → review_stage +1；6 个间隔全走完 → stage = mastered（已背熟），写入 mastered_at
   │  不认识/拼错 → review_stage 归 0，next_due_at = 明天
```

- **两个独立时间戳**：`memorized_at`（学完 5 轮）与 `mastered_at`（复习背熟），能回答"什么时候学完、什么时候背熟"。
- **词级复习**：艾宾浩斯复习按词调度（每个词自己的 `next_due_at`），不是按日期批次；`review_round` 记录当前间隔内的复习子步 0/1/2。
- **答错处理**：`wrong_count` 累计；拼错当场显示正确答案，不跳过；复习中不认识/拼错 → 间隔归零、明天再来。
- **幂等防重复**：更新带 `WHERE status='pending'`，影响 0 行即视为重复提交，直接返回最新 state，不报错、不跳词。
- **熟知捷径**：`POST /api/word/known` 把该词全部 progress 直接标 done + mastered，跳过学习和复习。

## 7. AI 内容生成链（带质量护栏）

三处用 AI：每日短文、周阅读题目、主观题判分。统一走 `llm.py` 的 `generate_text()/generate_json()`。

**短文生成**（`content.py`）：

1. 模型被要求返回 JSON（标题 + 正文），按选定场景写；
2. 用**与"点词释义"完全相同的词形还原表**校验目标词覆盖率（复数/过去式/句首大写都能匹配）；
3. 漏词 → 带缺失清单重写一次；仍不达标 → 退回本地模板（已重写为自然句式，无 "The word X appears here" 硬凑）；
4. 生成时把每个词的释义快照写入 `article_word`，保证"点开是生成当时的意思"。

**周阅读**：模型按文章一次生成 4 道四选一 + 1 道简答及评分要点，校验选项/答案格式；失败回退模板。主观题判分结果按"参考答案+作答"缓存（LRU），重复提交不烧额度。

**多源与降级**：主源智谱 + 兜底 Agnes，都是 OpenAI 兼容协议，地址/Key/模型名全从 `.env` 读，业务逻辑不写死模型名。无 Key 时全流程走本地确定性生成器，功能完全可用。

## 8. 互动与英语 AI 助手

**已有互动**：短文揭示后自动生成最多 5 道语境完形填空（干扰项取自同篇其他词，答错显示释义）；纯前端练习，不写库。

**英语 AI 助手（chat.py + ChatPanel.vue）**——这是设计上最克制的模块：

- **旁路性**：会话与消息只写 `chat_session`/`chat_message`，**不碰 progress/answer_log/两级状态**。实测对话前后 progress 75→75、answer_log 50→50。
- **真实语境（可选增强，不是边界）**：从短文或题目打开时，把文章正文、题干选项、以及 `article_word` 里的**真实释义快照**冻结进会话 `context`，回答关于这篇内容的问题时作为 ground truth 防编造；**从「我的 → 英语 AI」直接打开则没有语境，照样能查词、互译、讲语法**。
- **能力范围**：系统提示允许任意英语学习话题——中英互译、单词查询（释义/音标/词性/搭配/例句）、语法与句法分析、写作润色、阅读题讲解；非英语问题会礼貌拒答并引导回英语。
- **回答语言按问题类型决策（不默认英文）**：最高优先级是尊重用户显式指定的语言（"用英语解释 / 用中文回答"）；讲解/分析/语法/时态区别/句子结构/润色说明这类教学性内容，用户用中文提问就**主要用中文讲**，只保留被引用的英文词句和英文例句；汉译英先给英文词句再附中文注解；英译中先给中文核心释义再附简短英文例句；写作润色保留改后英文文本但用中文解释改了什么。这样中文学习者不必再翻译 AI 的回答。实测六类问题（虚拟语气/句子结构/时态区别/润色/词义/显式英文请求）语言方向全部正确。
- **考研风格出题**：识别到出题/批改意图时，服务端只读查询 `daily_plan + progress + word`，把**今天学的词**（最多 40 个，含释义快照）作为 `TODAY'S WORD BANK` 注入当轮 prompt。出题时**刻意丢弃当前文章 context**，并把用户已有 `article` 的标题与正文摘要作为 `PASSAGES ALREADY IN THE APP` 禁止复用清单，所以练习题是全新文章，不会把每日短文挖空。词库查询不写任何表，出题数据仍只在 chat 旁路里。
- **结构化交互题卡（cloze / reading）**：`POST /api/chat/practice` 让模型按**严格 JSON schema** 产出题目（正文、`options`、逐空/逐题的 `answer` 与中文 `explanation` 分离），`chat.py` 的 `_card_valid()` 校验字段与数量、失败重试一次（免费模型偶发漏字段/重复词）。题卡以 `[[PRACTICE_CARD]]` 标记前缀作为 assistant 消息存入 `chat_message`——不改表结构、且自然进入对话历史，追问时把答案与解析摘要喂回模型作依据。前端 `PracticeCard.vue` 把空渲染成 A–J 下拉框、把阅读题渲染成四选一单选，**判分纯前端比对、不消耗 token**；支持「就这题问 AI」「再做一次」。英译汉、大/小作文仍走文字出题 + AI 批改。
- **对话与刷题共存**：题卡只是「出题那条消息」的渲染方式，AI 的对话通道完全不变——同一弹窗里可自由聊天、生成交互题卡、答完继续文字追问，三者互不干扰。
- **成本与体验护栏**：最多 8 轮、只回传最近 12 条历史；普通回复 512 token，出题/批改/题卡生成自动切到 1200 token（`CHAT_PRACTICE_TOKENS`）、单请求超时放宽到 60 秒（`CHAT_PRACTICE_TIMEOUT`）；未配 Key 时禁止开启。弹窗内置快捷入口：选词填空·交互、阅读理解·交互、翻译练习、大作文、小作文。
- **三个入口**：通用「英语 AI」、短文「问 AI · 这篇文章」、周阅读逐题「问 AI」；点词卡片可「追问这个词」。
- **越权防护**：带来源的会话只在本人的 article/question 上建立，来源不存在或不属于本人直接 404。

## 9. 账号、权限与安全边界

- **身份**：除 health 与 auth 外，所有接口从 HttpOnly Session Cookie 解析 user_id，**绝不采信前端传来的用户 id**；跨账号访问一律 404。
- **口令**：PBKDF2 200k 轮 + 随机盐；密码框按模式区分 `new-password`/`current-password`。
- **限速**：登录/注册/管理员登录 5 次/60 秒锁定，成功清零。
- **注册继承竞态**：首次注册继承旧进度用 `SELECT ... FOR UPDATE` 行锁 + 当前读计数，避免并发重复搬数据。
- **管理员边界**：`ALLOW_LOCAL_ADMIN` 开关 + 拒绝 `X-Forwarded-*` 转发头，防止反向代理下外部访客提权；`GET /api/auth/users` 需管理员权限。
- **健康接口**：不回显数据库账号，页面不展示凭据。
- **模型边界**：Key 与 base_url 永不下发浏览器；模型切换只能在服务端白名单 `LLM_MODEL_PRESETS` 内选，非法名直接拒绝。
- **SQL**：全部参数化查询，注入面基本为零。

**并发与工程健壮性（已修）**：
- `GET /api/state` 纯读化：`fetch_state()` 不再写库，状态跃迁抽到 `advance_state()`，只由 `POST /api/answer` 成功后触发。实测 GET 前后 `daily_plan` 状态一致。
- LLM 调用挪出事务：`db.detach_for_llm()` 在生成前提交读事务释放锁，生成后靠文章表的 UNIQUE 键幂等写回（并发重复生成返回已有文章）。chat 出题/答疑同样在 LLM 前释放事务。
- 答题防重复：`mark_done()` 的影响行数由 `require_mark_done()` 检查，0 行返回 409；`answer_log` 幂等迁移加 `uk_exam_question(user_id, question_id)`，写入用 `INSERT IGNORE`，撞键时回读返回已有结果。实测 3 并发提交只写 1 行。
