## 二、🟡 架构 / 健壮性

### 3. 定时任务 `except Exception: pass` 吞掉所有错误
- **位置**：`backend/main.py` → `_scheduler_loop()`。
- **核查结论**：⚠️ **属实**。周阅读的定时发布（`_publish_due_week`）异常被静默吞掉，
  虽有「打开阅读页时兜底」覆盖，但生成失败时**无日志、无感知**，排障困难。
- **状态**：✅ **已处理**（2026-11-22）—— 改为 `logging.exception(...)` 记录异常，不再静默吞掉。

### 4. PBKDF2 不支持自动 rehash（老哈希不升级）
- **位置**：`backend/auth.py` → `hash_password()`。
- **核查结论**：⚠️ **属实**。新密码按 600k 轮（OWASP 2023）哈希；但老用户的 200k 轮哈希
  在登录时**不会自动升级**到 600k（`verify_password` 用存储值里的 rounds 校验，天然向后兼容，但没有触发重哈希）。
- **状态**：待处理 —— 可选：登录校验通过后检测 rounds < 600_000 时用新参数重哈希并回写。

### 5. `datetime.now()` 与 MySQL `TIMESTAMP` 的时区偏差
- **位置**：`backend/content.py` → `ensure_weekly()`、`reading_payload()`。
- **核查结论**：⚠️ **部分属实，当前无影响**。`datetime.now()` 取的是 Python 进程的本地时区（无时区信息的 naive 时间），
  与 MySQL `TIMESTAMP` 比较时依赖双方时区一致。**当前本机自用场景**（Python 与 MySQL 同机、均为中国时区）无偏差；
  但**未来部署到非 `Asia/Shanghai` 时区的服务器**时，`publish_at`/`deadline` 判断会产生偏差。
- **状态**：待处理 —— 部署前需统一时区（连接串加 `SET time_zone` 或用带时区的时间），当前不影响本机使用。

### 6. 前端 401 错误提示不友好
- **位置**：`frontend/src/api.js` → `api()`。
- **核查结论**：⚠️ **属实**。401 时只抛出 `HTTP 401` 字符串，界面仅显示这段文字，
  用户**不知道该去登录**（是未登录 / 会话过期）。
- **状态**：✅ **已处理**（2026-11-22）—— 会话过期/未登录时提示「登录已过期，请重新登录」；
  登录/注册接口的 401 保留后端「密码错误」等具体原因。
